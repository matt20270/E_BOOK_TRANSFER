# X4 Pro Reader Studio (웹 v0.4.0)

설치 없이 브라우저에서 쓰는 전자책 변환·TXT 정리 사이트입니다. 서버가 없고 **파일은 기기 밖으로 나가지 않습니다.**

## 할 수 있는 일
- **PDF → EPUB**: 변환 전에 모드를 고릅니다.

  | 모드 | 쓰는 엔진 | 잘하는 것 | 속도(브라우저, 쪽당) |
  |---|---|---|---|
  | **책 모드** (기본) | PP-OCR 한국어(PaddleOCR) + 글줄 펴기 | 사진 위 글씨, 기울어지거나 휘어진 글씨, 파란 배경의 흰 글씨 | 약 4~8초 |
  | **논문 모드** | Docling(구조 분석) | 2단 편집 읽기 순서, 제목, 그림·표·수식 영역 분리. 글자가 있는 PDF는 OCR 없이 PDF의 글자를 씀 | 글자 PDF 약 3~8초, 스캔 PDF 약 10~30초 |
  | **빠른 모드** | Tesseract | 깨끗한 흰 바탕 글 (기존 방식) | 약 1.5~2초 |

- 공통: 쪽 번호·머리말 자동 제거(책·빠른 모드), 제목으로 목차 만들기, 쪽마다 "글 / 쪽 이미지 / 글+이미지 / 제외" 선택, 인식이 불확실한 단어 노란색 표시와 직접 수정, 쪽 범위 선택, 최대 5GB PDF.
- **TXT 정리**: 줄바꿈이 엉킨 TXT를 문단으로 복원 (UTF-8/CP949 등 저장).

## 큰 파일 올리기 (v0.4.0에서 처음 필요합니다)
이번 버전은 인식 모델 파일이 커서(합쳐서 약 110MB, 가장 큰 것이 약 66MB) **GitHub 웹 업로드로는 올릴 수 없습니다.** 무료 프로그램 **GitHub Desktop**을 쓰면 터미널 없이 올릴 수 있습니다.

1. https://desktop.github.com 에서 GitHub Desktop을 설치하고 GitHub 계정으로 로그인합니다.
2. **File → Clone repository…** 에서 이 사이트의 저장소를 골라 **Clone**합니다. (내 컴퓨터에 폴더가 하나 생깁니다. **Show in Finder**로 열 수 있습니다.)
3. 받은 **업데이트 ZIP**(코드)과 **모델 ZIP**을 풉니다. 그 안의 폴더·파일을 **복제된 폴더 안에 그대로 덮어쓰기(병합)** 합니다. `vendor` 폴더가 있으면 "병합"을 고르세요. (교체를 고르면 기존 파일이 지워질 수 있습니다.)
4. GitHub Desktop 화면에 바뀐 파일 목록이 나타납니다. 왼쪽 아래 **Summary**에 `v0.4.0`이라고 적고 **Commit to main**을 누릅니다.
5. 위쪽의 **Push origin**을 누릅니다. (50MB가 넘는 파일이 있다는 경고가 나올 수 있는데, 100MB 미만이면 올라갑니다.)
6. 1~2분 뒤 사이트에서 **Cmd+Shift+R**로 강력 새로고침합니다.

모델 ZIP을 받을 수 없으면 `vendor/MODELS.md`의 주소에서 파일을 직접 받아 같은 폴더에 넣으세요. 파일이 하나라도 없으면 변환 시작 때 "인식 엔진을 불러오지 못했습니다"가 나옵니다.

## 사용 순서 (PDF → EPUB)
1. PDF를 고르고 **변환 모드**와 옵션을 정한 뒤 **변환 시작**을 누릅니다. 진행률과 남은 시간이 표시됩니다.
2. **검토 및 수정**에서 쪽을 넘기며 확인합니다. 왼쪽은 원본 쪽, 오른쪽은 인식된 글입니다. 노란 글자는 인식이 불확실한 단어입니다. 논문 모드에서는 그림·표·수식이 "그림/표/수식" 행으로 나오고, 삭제로 제외할 수 있습니다.
3. 인식이 나쁜 쪽은 **이 쪽 다시 인식** 버튼을 쓰세요. (책 모드: 고해상도로 다시 읽기, 빠른 모드: 기울기를 바꿔 다시 읽기)
4. 책 제목·저자를 입력하고 **EPUB 만들기**를 누릅니다.

## 알아 두세요 (한계)
- **책 모드의 정확도**: 예시 책(사진 위 기울어진 글씨) 12·100·140쪽에서 정답과의 일치도(F1)가 0.86~0.97이었고, 빠른 모드(Tesseract)는 0.46~0.59였습니다. 그래도 몇 글자는 틀리고("바삭"→"바작"), **띄어쓰기가 부정확합니다.** 구두점 뒤 공백은 규칙으로 보정하지만 단어 사이 공백이 빠지는 경우("라틴어로파니스")는 직접 고쳐야 합니다. 줄 끝에서 한 단어가 갈라질 때 공백이 들어가기도 합니다.
- **논문 모드**: 글자 PDF 경로는 PDF 100MB까지만 지원합니다(그보다 크면 쪽 이미지 OCR 경로). 표는 **이미지로** 넣습니다(표 구조 복원 모델은 380MB라 넣지 않았습니다). 소제목은 번호가 붙은 것("1. Introduction")만 확실하게 구분됩니다. 스캔 논문에서 영어는 "인식 언어: 영어"를 고르세요. "한국어+영어"는 한국어 모델이 영어도 읽지만 철자 오류가 조금 늘 수 있습니다.
- **X4 Pro 기기**: 순정 펌웨어는 EPUB 안의 이미지를 못 보여 줄 수 있습니다(제조사 매뉴얼). 기기 전용 **XTC 형식 출력은 아직 없고** 다음 단계로 개발할 예정입니다. 쪽 이미지 크기 "960×1600"은 일부 기기의 이미지 한계(1024)를 넘으니 "480×800"을 권합니다.
- PDF 용량 상한: 50MB 초과는 경고 후 허용, **5GB 초과는 열 수 없습니다.** 최대 5000쪽. 큰 파일은 쪽 범위로 나눠 변환하는 편이 안정적입니다.
- 휴대폰은 메모리가 적어 큰 PDF에서 느리거나 멈출 수 있습니다. 큰 PDF는 PC/맥북을 권합니다.
- Chromium(Chrome 계열)에서만 자동 시험했습니다. Safari·Firefox, 실제 X4 Pro 기기에서는 확인하지 않았습니다.

## 보안 설계
- `connect-src 'none'`: 브라우저가 외부 서버로 어떤 데이터도 보내지 못합니다. CSP는 `default-src 'self'; script-src 'self'; style-src 'self'; ...` 그대로이며 **완화하지 않았습니다.** (인식 엔진은 별도 작업자(Worker)에서 돌아서 `'wasm-unsafe-eval'`도 필요 없습니다.)
- 모든 라이브러리와 모델은 `vendor/`에 내장되어 있고 외부 CDN을 쓰지 않습니다.
- PDF·OCR에서 나온 글은 `textContent`/`createTextNode`로만 화면에 넣습니다 (`innerHTML` 사용 없음). EPUB에는 XML 특수문자를 이스케이프하고 금지 문자를 제거해 넣습니다.
- 파일 크기(PDF 5GB·TXT 50MB)·쪽수(5000)·쪽 한 장의 픽셀 수·EPUB 이미지 합계(1GB) 상한, 다운로드 파일명 정제, `.gitignore` 적용.
